## **Суть решения (обязательно к пониманию)**

1. **Модель — это данные, а не часть приложения.** Тулза весит мегабайты. Веса (~0.5–1 GB) лежат в папке `models/` на диске и скачиваются один раз при первом использовании автотеггера.
2. **Offline-first.** После первичного скачивания работа без интернета: датасеты часто гоняют на машинах без сети.
3. **Ленивая загрузка.** Веса попадают в память по первому запросу к автотеггеру, а не при старте сервера. Есть явная выгрузка для освобождения RAM/VRAM.
4. **Прозрачные состояния.** UI в любой момент знает статус модели: не скачана → скачивается → загружается → готова → ошибка. Никаких молчаливых ожиданий.
5. **Поточная обработка.** Батч на сотни картинок отдаёт caption'ы через SSE по мере готовности, с прогрессом по каждому файлу.



У самого теггера должен быть выбор между типом автотеггинга: описание картинки тегами или натруальным яызком (регулируется в самой модели через промпт с инструкцией).



Должна быть возможность выбирать, для каких фото делать автотеггинг (выбор нескольких фото, всего батча и тд.)





Выбор CPU (с пометкой медленно), GPU (если доступно)
